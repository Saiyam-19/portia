# Actual-tariff estimate: bounded implementation plan

Goal: one realistic, independently frozen actual-port-tariff request reaches the existing local UI, main/specialist tools, exact calculation, cited answer, durable messages and reload. The supplied-quotation journey remains a separate historical result.

Constraints: all16ports/features retained; preserve17assets and existing frozen19/24/12inputs; no broad source research, UI change, provider migration or deployment. Sole writer: implementation chat. Source author freezes one source/input/oracle independently; requested charge scope and approved packet are pending. No inference until explicit approval and offline success. Then at most8free dispatches total, counting main and specialists, same dedicated key, retries0, fallbackfalse, zero price ceilings.

## Verified integration points

- `ports.ts` verifies bundled file hashes but returns untyped historical/reference text. Preserve that loader and all old versions.
- `consult_port_agent` currently invokes a specialist with arithmetic tools, then returns prose/report. Successful arithmetic and a `tariffConsulted` flag do not establish source applicability or requested-scope completeness.
- `reviewed-report.ts` preserves a model-reviewed report verbatim; it does not bind charge rows to tariff rules. It remains for existing paths.
- The supplied-quotation route already demonstrates server-side ledger recomputation, commit-before-display and deterministic final text. Reuse that publication pattern while retaining a distinct actual-tariff evidence class and source/rule validation.
- `CallContext` currently supplies trusted GT, duration/timestamps and port identity, but not every tariff eligibility field. Add only facts actually required by the approved scope, using authenticated user/form provenance. Do not infer missing eligibility from a model-written consultation query.

## Work order and acceptance

1. **Preparation, now:** preserve entry baseline; trace existing consultation/publication; add a local acceptance transport budget that durably counts up to8dispatches across main/specialist calls and server restarts. No provider traffic and no guessed rates. Source/rule/ledger interfaces remain governed by `docs/portia-reliability/contracts.md`.
2. **After source/input freeze:** store the approved source version additively with original publication URL, issuer, content hashes, passages and effective scope. Encode only approved rate, eligibility, quantity units, period/minimum, rounding and tax dependencies. Oracle amounts live in acceptance evidence/tests only, never production rule data.
3. **Execute through existing tools:** main selects the port or asks necessary missing facts; specialist sees the approved published clauses and selects applicable rule IDs. A bounded tariff calculator validates source version, eligibility and user fact bindings, then derives expressions using the decimal engine. No free-form model formula can certify a tariff ledger.
4. **Publish only complete requested scope:** tariff-specific ledger records base charge, required tax, rounding and dependencies, with source/rule references and run/context binding. Missing required facts/clauses yield focused clarification or explicit incompleteness. Renderer derives names, monetary rows, total and citations from that ledger. Route recomputes/validates before the existing atomic fenced completion, then streams the same saved text.
5. **Offline gates:** unchanged independent source/input/oracle; positive ordinary case and necessary eligibility/period/unit/tax/rounding neighbors; reject swapped/invented values, stale bindings and failed persistence. Preserve D01/D11/scenario19. Use focused tests, typecheck/build; do not repeat unchanged broad checks.
6. **One genuine local journey:** only after approval/offline success; same pinned free model, max8dispatches with no retries/fallback. Record all dispatches, source citations, exact input, streamed/displayed answer, persisted completion and reload. Stop on systemic failure. Clean up owned processes and retain prior listeners.

Source-dependent implementation is intentionally pending the approved packet and scope decision. A berth-only request must not be labelled an all-port-call total; a full-call request cannot omit mandatory requested charges.
