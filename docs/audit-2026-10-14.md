# Portia website and agent audit

14 October 2026. Audited commit `b64420fcfe0eea206918bfb34cf9cf38112b8302`, branch `main`, initially clean. This is a full product snapshot review, not a branch diff. Product code, dependencies, credentials and deployed configuration were not changed.

**Result: audit not clean. 13 findings: 1 P1, 10 P2, 2 P3.** The most consequential specification failure is deletion of unrelated chat notes. Standards findings include ineffective application body-read limits, excessive memory polling and an unhandled cancellation rejection. No owner-isolation bypass was found in the tested paths.

**Paid inference: zero calls, $0 incurred by these tests.** Local HTTP and browser journeys used the real production build, real local Convex and Better Auth, actual agent orchestration and OpenRouter adapter, with an injected synthetic provider and a nonfunctional provider credential. Unit tests blocked default fetch. No live VesselAPI calls were made. The approved npm advisory scan sent package metadata to npm. Public production checks were limited to three unauthenticated GETs.

“Every edge case that can ever exist” is unbounded. This report records the tested boundaries, reproducible failures and remaining uncertainty; passing tests are not proof of universal correctness.

## Standards findings

### T1 P2 Request limits do not bound body consumption

**Locations:** `src/app/api/migration/chat/route.ts:72`, `src/app/api/migration/cancel/route.ts:15`.

Chat checks a declared Content-Length, then reads `request.text()` in full before enforcing 32,000 actual bytes. Cancel similarly buffers before enforcing its smaller limit. Content-Length may be absent or dishonest. Origin validation is not authentication: an arbitrary HTTP client can supply the expected Origin.

**Reproduction:** a synthetic chunked body supplies 100 chunks of 1,000 bytes without Content-Length. Both handlers consume all 100 chunks before rejecting. Tests expect the reader to stop near the documented boundary and fail. Rejection prevents inference, but does not prevent the allocation/read cost. Hosting-level ceilings constrain practical exposure and were not stress-tested.

**Action:** stream bytes into a bounded buffer, cancel once over limit, and authenticate before expensive work where practical. Preserve the fast wrong-origin rejection, which passed its no-body-read control.

### T2 P2 Memory lease contention multiplies backend calls

**Location:** `src/lib/memory/session.ts:37`.

When another worker holds a memory lease, `drain()` performs `claim` and `open` every 75 ms, for up to 45 seconds. The fake-clock probe measures **28 bridge requests in the first second** with negligible response latency. Longer contention and multiple waiters multiply this. Real network latency lowers the observed rate; this measurement is not a production bill.

These are Convex HTTP/auth/mutation calls, not model inference. A fixed fast polling interval wastes backend capacity even though model retries are disabled.

**Action:** return retry/lease timing, apply bounded exponential backoff with jitter, stop promptly on cancellation and avoid duplicate per-user waiters. Retain deletion barriers and fence validation.

### T3 P2 Runtime dependency tree contains known advisories

**Location:** `package-lock.json`; `just-bash@3.6.0 → guarded-fetch@0.1.3 → undici@7.29.0`.

The npm scan reports one high-severity package record for the nested Undici version, plus six moderate package records. The separate AI SDK dependency uses `undici@7.30.0`; it is not the affected nested copy.

The maintainer documents affected versions and patched `7.29.1` for the [WebSocket handshake denial of service](https://github.com/nodejs/undici/security/advisories/GHSA-rfgv-xxqx-mfg5) and [BalancedPool TLS-option loss](https://github.com/nodejs/undici/security/advisories/GHSA-w293-vg96-wgc3). Other records concern `sprintf-js`, selector parsing and browser mapping, including parent-package propagation.

**Reachability:** application memory exposes typed SQLite operations and virtual files, not a general shell, arbitrary WebSockets or BalancedPool. An exploit through those high-severity paths was **not demonstrated**. CSS/parser dependencies largely affect build-time processing here. The dependency finding still warrants remediation; it is not an assertion of a remotely exploitable breach.

**Action:** update the owning dependency/lockfile to a reviewed compatible patched tree and run memory/tool regressions. Do not blindly apply npm's proposed typography downgrade. No dependencies were updated during this audit.

### T4 P2 Authentication errors lack an accessible notification

**Location:** `src/components/auth/login-form.tsx:132`.

Invalid credentials render visible text in an ordinary `div`. Browser inspection confirmed `role=null`, `aria-live=null`, and no alert/live-region ancestor. The error is not linked to the fields or deliberately focused. Users relying on announcements may not discover the failed submission.

**Action:** provide a suitable alert/live region and field association, retaining safe public wording. Verify with a screen reader; this audit inspected DOM semantics but did not perform a complete assistive-technology certification.

### T5 P3 Mobile navigation does not expose expansion state

**Location:** `src/components/navbar.tsx:49`.

The landing-page menu visibly opens, but “Toggle menu” has no `aria-expanded` or `aria-controls`. The same label is exposed in both states.

**Action:** connect the toggle to the menu, expose expanded state, and verify keyboard dismissal/focus. The authenticated sidebar uses the shared dialog implementation and behaved better in the inspected keyboard flow.

### T6 P2 Provider cancellation leaks an unhandled rejection

**Boundaries:** `src/lib/migration/safe-model.ts:59`, `src/lib/migration/reviewed-report.ts:65`, `src/lib/migration/public-stream.ts:4`, `@openrouter/ai-sdk-provider@3.1.0`.

**Reproduction:** start a real local chat request; wait until the synthetic provider has begun; cancel via `/api/chat/cancel`. The durable state becomes `stopped` and the HTTP stream ends, but Next logs `unhandledRejection: AbortError: Stopped by user.` This occurred twice.

`tests/audit/cancel-stream.audit.ts` isolates the distinction: an equivalent SDK mock stream passes; the actual OpenRouter adapter with injected fake fetch plus application wrappers produces one unhandled rejection. Vitest exits 1 even though its two stream assertions pass. This is an integration failure that a simple successful cancellation-state assertion misses.

The adapter contains a discarded `reader.cancel(reason)` promise, but standalone adapter cancellation probes did **not** reproduce the leak. The exact causal promise is therefore still unconfirmed. Do not present that source observation as a proven root cause. No real provider outage or process crash was induced; the local server remained healthy.

**Action:** use the isolated failing adapter regression to trace and handle the rejected promise through abort/cancel paths; verify both saved state and absence of unhandled errors. Evaluate dependency changes against this test before release.

Standards total: **6 findings**. The body-consumption and cancellation failures are the strongest directly executed reliability findings; dependency severity is qualified by reachability.

## Specification findings

### S1 P1 Deleting an empty chat erases unrelated working notes

**Locations:** `convex/lib/memoryLifecycle.ts:51`, `convex/lib/memoryLifecycle.ts:87`.

`docs/memory-integration.md` says deletion removes the conversation's notes and provenance. Global note invalidation is described for forgetting memory. Implementation enqueues a global `delete_source` barrier for every deleted conversation once a memory namespace exists, even if that conversation has no saved facts. The barrier increments the user's epoch, deletes older notes across chats and fences independent runs.

**Reproduction:** active chat A has “Independent chat progress”; B is empty and contributed no facts. Delete B. A's notes become an empty string. A's attempted completion also fails `MEMORY_CHANGED`. Two regression assertions reproduce the two consequences of this one defect.

**Impact:** unrelated task progress is lost and another running estimate can fail. Unlike clearing explicitly selected memory, this happens during deletion of an unrelated empty chat.

**Action:** distinguish deletion that changes shared memory from deletion that only removes the target chat. Preserve the privacy barrier where shared facts really change; do not globally invalidate independent notes for a no-op source deletion.

### S2 P2 A full memory queue prevents chat deletion

**Locations:** `convex/lib/memoryLifecycle.ts:52`, `convex/migration.ts:397`.

The documented immediate root revocation occurs after memory enqueue. Once 96 deletion barriers remain pending, enqueue throws `MEMORY_BUSY`; the transaction rolls back and preserves the conversation root. This also reproduces with memory disabled after prior use, while the normal memory bridge is unavailable to drain the queue.

**Reproduction:** initialize a namespace, enqueue 96 pending clear barriers, then delete an owned chat. Both memory-enabled and memory-disabled cases reject deletion and retain the root. Equivalent pressure can arise from undrained source deletions.

**Action:** make root revocation admissible under queue pressure, using a safe coalesced/tombstone cleanup design. Do not drop the memory deletion barrier or allow stale writers to restore deleted data.

### S3 P2 Parallel tool calls bypass the specialist limit

**Location:** `src/lib/migration/domain-agent.ts:128`.

Architecture promises at most three specialist consultations per run. The implementation checks the counter, awaits tariff loading, then increments it. The installed AI SDK executes same-step tools concurrently.

**Reproduction:** a fake main model emits four `consult_port_agent` calls in one step. Four specialists are created. The existing sequential-limit test passes and does not cover this race. The separate 16-provider-call counter still bounds total model calls; this finding does not establish unlimited inference.

**Action:** reserve the specialist slot synchronously before the first await and define how unavailable/empty data releases or consumes it. Test parallel requests at the boundary as well as sequential ones.

### S4 P2 Valid Unicode questions break initial navigation

**Location:** `src/app/dashboard/page.tsx:39`.

The composer accepts up to 4,000 characters, then places the complete first question into a URL query. Percent encoding can expand it several times. On the actual local production server, 1,000 copies of `航` produce a 9,051-byte path and HTTP 200; 2,000 produce an 18,051-byte path and HTTP 431; 4,000 produce 36,051 bytes and HTTP 431.

The browser's 2,000-character submission creates an empty conversation and stays stuck at the disabled “Starting conversation” state. The error is an asynchronous navigation failure, so the mutation's try/catch does not recover the UI. A fresh navigation restores the workspace.

**Action:** keep question text out of the URL. Persist an owner-scoped initial draft/request or pass a bounded intent identifier, then POST the text. Preserve existing request idempotency and reload protection. This also avoids putting prompt text into navigation history and request logs.

### S5 P2 Structured form fields accept values the server rejects

**Locations:** `src/components/chat/form-card.tsx:30`, `src/lib/migration/contracts.ts:69`.

The server caps each form value at 2,000 characters. The ordinary text and textarea fields have no matching `maxLength`; only the additional-context note is bounded.

**Reproduction:** enter valid tonnage and 2,001 characters in optional Remarks. Continue stays enabled. Submission fails and shows the generic response-failure message without identifying the too-long field. Reducing Remarks permits submission and preserves values/note after reload. The server correctly rejects the oversized value; the defect is client validation and actionable feedback.

**Action:** align client/server limits, announce the offending field and preserve the form draft. A new static rendering regression reproduces the missing bounds.

### S6 P2 Visible navigation and consent links lead nowhere

**Locations:** `src/components/auth/login-form.tsx:155`, `src/components/footer.tsx`, `src/components/navbar.tsx:34`.

Local route requests return 404 for `/terms`, `/privacy`, `/about`, `/blog` and `/contact`. Both Pricing anchors target a nonexistent `#pricing` section. The public production site also returned 404 for Terms and Privacy during read-only GET checks, while its homepage returned 200.

The login screen says continued use agrees to documents users cannot open. The remaining dead links misrepresent available site content.

**Action:** supply the intended pages/section or remove unavailable destinations and misleading agreement copy until real documents exist. This is a product-consistency finding, not a legal-compliance opinion.

### S7 P3 Sanitization loses transient network-error classification

**Locations:** `src/lib/migration/safe-model.ts:16`, `src/lib/migration/error-reporting.ts:24`.

The sanitizer retains `errorType: 'network'` on a new safe Error. The later classifier ignores that field, so errors such as `ECONNRESET`, `ENOTFOUND` and `UND_ERR_SOCKET` become generic failures rather than the intended temporary-busy guidance. Three error-code variants reproduce it. Private provider text remains hidden.

**Action:** preserve recognized safe classifications through the boundary without restoring raw provider errors, headers or bodies.

Specification total: **7 findings**. Highest severity: **S1, unrelated note loss and interruption**.

Shared components, scoped theme behavior, labels, safe Markdown rendering, explicit interrupted-work copy and form persistence are strengths. Four detector font-size advisories are minor design-ramp deviations, not reasons to redesign the UI.

## Tariff and domain evidence

The bundle contains **17 Markdown files across 16 port/terminal slugs, 388,242 bytes and 5,805 lines**. All byte-parity tests against legacy assets pass. BPCL cargo jetty's asset is empty; its explicit unavailable fallback passes and must not silently substitute the liquid-jetty tariff.

Tariffs are static and include historical dates, expiry language and OCR-damaged table content. Targeted source review and file integrity are not a current-authority, clause-by-clause rate certification. Five tariff documents have graph parsing gaps; text was used for relevant checks. No present-day port-rate claim is made by this audit.

Mumbai alone contributes **167,817 bytes** before prompt framing. Specialists currently receive the complete port bundle. This is a concrete input-size cost driver, especially across repeated consultations. Token counts/prices depend on the configured model and were not estimated from bytes as if they were exact tokens.

## Cost priorities

1. Repair the parallel specialist reservation race and memory contention polling first; both spend resources without adding intended behavior.
2. Preserve `maxRetries: 0`, explicit paid opt-in, shared call limits and same-request recovery. Tests confirmed idempotent retry does not invoke the provider again.
3. Introduce deterministic section selection or indexed tariff retrieval with provenance before sending entire large schedules repeatedly. Validate recall on tariff boundary fixtures before reducing context.
4. Keep the existing reviewed-report publication and batch calculator; regression evidence covers these cost-saving paths.
5. Consider a real monetary/input-token budget and concurrency limit if operating public signup. Current per-user request windows are not a spend ledger; arbitrary new accounts can expand aggregate spend. This is a known product limitation, not an undisclosed claim that the current limits enforce dollars.
6. Re-run deterministic tests before purchasing small real-provider acceptance samples. Synthetic success proves contracts and lifecycle, not model judgment or upstream availability.

## Reproduction and artifacts

Use Node 22. Check existing processes/ports first. Existing dependencies suffice; no install or deployment is needed for the unit suite.

```sh

node node_modules/vitest/vitest.mjs run --config vitest.audit.config.ts tests/audit/cancel-stream.audit.ts

```

The second command should report the intentional failing expectations and the unhandled cancellation error on the audited snapshot. Baseline and audit results must not be collapsed into a single “all tests pass” claim.

Reusable files:

- `vitest.audit.config.ts` and `tests/audit/`: adversarial requests, arithmetic properties, memory deletion/queue, UI bounds/rendering and cancellation isolation.
- `scripts/audit/synthetic-provider.cjs`: OpenRouter fetch substitution. Uses a synthetic key, returns deterministic SSE and records only local audit metadata.
- `scripts/audit/local-api.mjs`: real local auth/database/API journeys; refuses to run without the local lab descriptor and explicit synthetic-provider flag.
- `scripts/audit/provider-cancellation.mjs`: standalone adapter controls. They did not reproduce the integration leak and are retained as narrowing evidence.

To reproduce local journeys, start the existing lab in an interactive terminal with the substitute preloaded, never the ordinary live verification command:

```sh
mkdir -p .local/audit-20261014
OPENROUTER_API_KEY=synthetic-audit-key \
NODE_OPTIONS="--require=$PWD/scripts/audit/synthetic-provider.cjs" \
node --experimental-strip-types scripts/memory-chat-lab.mts
```

After `READY`, in another terminal:

```sh
PORTIA_AUDIT_SYNTHETIC_PROVIDER=true node scripts/audit/local-api.mjs
```

Do not enter the lab's `verify` command: that is its separate live-model acceptance workflow. Enter `stop` in the lab terminal when finished. The harness records owned PIDs/groups and cleans them. The normal migration/memory documentation also explains the lab's local-only target checks.

Detailed ignored evidence lives in `.local/audit-20261014/`: JSON test reports, process ledgers, scan/build logs, source-asset inventory, public status codes and screenshots. Initial harness mistakes were corrected: the reserved `.invalid` account domain, generic 409 denial expectations, an absent optional tsx loader and closed stdin. They are not counted as product defects. The final documented failures persist after those corrections.

The current `.next` output was built for the isolated local lab; rebuild with the intended environment before using a different runtime or deployment. This audit did not deploy it.

## Completion and limitations

All reported source findings refer to the unchanged audited snapshot. Checks use graph discovery plus direct source/dependency inspection; the initial graph inventory contained 225 files and coverage was explicitly checked. A clean coverage signal is not proof that every construct was indexed.

Audit-only tests and documentation were added. No product repair, commit, push, production database mutation, account deletion or provider spend occurred. Local synthetic records remain only in stopped, ignored audit databases. The process cleanup result and final verification ledger are recorded alongside this report's evidence.

Cleanup verified: all owned finite workers have empty survivor lists; the lab's process registry marks every child stopped; ports **3022, 3220 and 3221 are closed**. Existing listeners **3000, 3210, 3211, 5174, 5198 and 9749** remain. Existing browsers and graph infrastructure were reused; temporary audit tabs were closed and the responsive viewport override reset. Unrelated services and Codex-managed helpers were preserved because none met the evidence threshold for safe stale-process termination. The audit is complete as a bounded source, adversarial, local integration and UI assessment. It is not an assertion that every possible input, tariff, browser, infrastructure failure or future model behavior has been tested.
