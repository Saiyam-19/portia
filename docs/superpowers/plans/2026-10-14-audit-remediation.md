## Implementation order and ownership

### R2 binding revisions

These refine and override shorthand in the table:

- **T1:** never await cancellation settlement before returning a bounded-read rejection. Attach a rejection handler to cancellation, release the reader lock, and return independently even if the underlying cancel promise never settles. An abort listener cancels a pending read; remove listeners on every terminal path. Treat malformed UTF-8/JSON as invalid; actual bytes decide the bound. Preserve auth-before-body on Convex bridges.
- **T2:** a single drain deadline clips both each bridge HTTP request and each backoff wait. Use the earlier of remaining drain time and normal15s bridge timeout. Abort cancels either immediately, removes timers/listeners, and never retries afterward. Reset backoff only after a successful publish; STALE_WRITER does not reset it.
- **T3:** restrict both serving and prototype Bash runtime commands to sqlite3. Shell syntax/builtins are not a general security sandbox; the application still calls a fixed command with typed arguments and quoted values. Test printf aliases, command/builtin prefix, awk, curl/wget, Python and JS. Residual sprintf-js and parent advisory is explicitly reported as mitigated, not erased or upgraded.
- **T4:** disable switching auth tabs while submitting, and guard duplicate submission. Error alert/association clears before each attempt. No aria-invalid for a network failure.
- **T5:** Escape closes the disclosure. Restore toggle focus only if focus was within this navigation; external focus must not be stolen. Activation of a link closes without refocusing the toggle.
- **S2:** explicit conservative maximum queue640: once backlog reaches ordinary cap96, no new ordinary operation can enter. Effective new source barriers can reference only the at-most512 applied source references plus at-most32 admitted pending remembers; partial drains cannot introduce a source outside this union. Each conversation root can contribute one barrier, atomically/idempotently; barriers/deletions do not add sources. Thus96+512+32 bounds each saturated excursion; falling below ordinary thresholds starts a new such excursion. Use bounded reads covering640 pending records and a fail-closed invariant guard for corrupt/out-of-contract larger state. No caller-supplied bypass flag: private deletion helper proves relevance in the same transaction. Add effective-source saturation and partial-drain/admission tests, not only empty-chat tests.
- **S4:** create stable request ID in the client BEFORE mutation; reuse it with unchanged normalized question+alias after lost response. Add owner/creationRequestId index and retained creation payload hash for deduplication even after intent is consumed; changed payload with same ID conflicts. Rev0 claim must match stored normalized text, alias and request ID. Stored intent outranks all legacy query arguments. Lock selector/composer while intent exists, including preclaim failure; offer explicit Retry saved question using the same immutable intent. Editing/replacing this pending intent is NOT introduced: existing New conversation or Delete actions are available. Consequently no hidden supersession can resurrect an old edited question. A newly edited draft on the new-chat page gets a new creation ID; an ambiguous old save may remain as its own saved chat. Old empty rows/no-intent creates and bounded legacy-only query links remain supported. Legacy changes never override a stored intent.
- **S5:** keep2000-character per-value bounds, explicit validation of numeric-string lengths, and note validation for Cancel as well as Submit. Before invoking transport, serialize the entire actual request (IDs, keys, model, note, values) and enforce the same32000-byte aggregate bound in the client. On excess, show specific shortening guidance and preserve all field state; no network request. Test eight2000-character CJK fields, escaped controls and exact-byte boundary. Do not manually slice strings/surrogate pairs. Cancelling ignores invalid unused field values but still validates the note/body.
- **S7:** bounded/cycle-safe cause inspection collects only recognized types; type precedence timeout > cancelled > invalid_response > network. Keep first valid outer-to-inner HTTP code. UI precedence: timeout or408/504;402 billing;401/403 configuration;429/5xx busy;network fallback;generic failure. Thus a nested network cause cannot erase timeout or mask credential/billing status. Explicit user cancellation still persists stopped. Repeated sanitization is idempotent; never expose raw provider text.

Root owns writing. Implement approved changes in dependency order: shared body/error primitives; memory source deletion/admission and backoff; agent budget/cancellation; durable initial intent; UI/accessibility/link cleanup; dependency compatibility updates.
