# Evaluation notes

A single pass-rate hides several different questions: whether an action executed, whether the user finished the task, and whether the answer was true. Report these separately. A necessary clarification can be correct while the requested estimate is still unfinished; a confident total can be delivered successfully yet be wrong.

Use separate denominators for complete supplied quotations, sourced tariff estimates, rule explanations, clarifications, corrections/comparisons, memory, cancellation and persistence/recovery. Report both public models separately. Keep FAIL, SAFE_INCOMPLETE, UNRESOLVED_ORACLE, BLOCKED_ENVIRONMENT, NOT_EXERCISED and NOT_RUN visible. Never count a missing reference or a run that finished before Stop as a pass.

To prevent over-refusal, retain ordinary successful requests and exact supplied-rate benchmarks. A complete quotation needs arithmetic, not a live official tariff or unrelated vessel particulars. Grade unnecessary questions and generic refusals explicitly. With incomplete inputs, judge the relevance and number of questions, then score completion after clarification. When a source is absent, reward an accurate limitation without pretending the requested current-rate answer was completed.

To prevent oracle contamination, obtain authoritative documents and amendments independently of the application's corpus and outputs. Freeze document identity, publisher, URL or controlled copy, effective dates, supersession evidence, pages, clauses, units, rounding, concessions, taxes and FX rules. Derive reference line items before seeing candidate answers. Having the tested model generate or approve its own expected answer is not an independent oracle. Synthetic quoted rates test arithmetic only and never establish official tariff truth.

Every monetary tariff reference remains unresolved until that independent source work is finished. Catalog membership is neither rate coverage nor freshness. Two plausible citations can disagree; an independent reviewer must resolve authority, scope and effective-date conflicts rather than rewarding whichever source the candidate happened to choose. A later all-charge/rule/exception inventory can reveal missing reference obligations.

The development/holdout split was authored before implementation feedback. Share only development.json with implementers. Record the sealed-holdout.json hash now; freeze candidate revision, prompts, configuration, model/provider settings and development results before opening it. The seal is procedural, not filesystem security. If a holdout case leaks or is repeatedly tuned against, retire it and author a fresh independent replacement. Report any post-freeze changes and distinguish first exposure from reruns.

Mocks can validate parsing, deterministic arithmetic, UI transitions and controlled failure handling. They cannot prove real model tool selection, current source retrieval, authentication ownership, provider cancellation/billing, live vessel lookup, or deployed behavior. Preserve the evidence boundary for each claim. For a cancellation race, capture the run identity and actual in-flight state; for deletion/forgetting, check durable state in an independent fresh view, not merely that a bubble disappeared. Existing transcript text is not the same as durable memory.

This author ran no application scenario, inference request or paid API. Arithmetic references used independent Python Decimal calculations with explicit half-up rounding where required; elapsed times used Python datetime subtraction of ISO-offset timestamps. Artifact structural checks and numeric-reference checks are evidence about the pack, not evidence that Portia passes it. Thirty-six finite scenarios cannot prove universal correctness. Report failure severity and user impact alongside rates, and add reference-backed cases when the full tariff inventory exposes more rules.
